# 引き継ぎ手順

別マシン（Mac ↔ Windows）で続きの作業をするための復元コマンド。
以下を **順番に、省略せず** 実行し、最後に日本語でまとめて報告すること。

## 1. リポジトリの状態を確認

```bash
git status -sb && git log --oneline -10 && git fetch --dry-run 2>&1
```

- 未コミットの変更があるか
- `origin/main` より進んでいる／遅れているか
- 遅れている場合は「`git pull` しますか？」とユーザーに聞く（勝手に pull しない）

## 2. プロジェクト文脈を読み込む

- `CLAUDE.md` — 構成・編集の大原則・注意点（自動で読み込まれているはず）
- `WORKLOG.md` — **前回どこまでやったか / 次にやること**。必ず読む
- 必要に応じて `js/contents.js`（全テキストデータ）

## 3. 環境チェック（このマシンで初回のみ）

`.claude/launch.json` があるか確認する。
無ければ、この OS 用の設定を `CLAUDE.md`「ローカルプレビュー」の内容で作成する。
（Windows は `python`、macOS は `/opt/homebrew/bin/python3`）

## 4. 整合性チェック

`js/contents.js` が参照している画像がすべて実在するか確認する：

```bash
grep -oE "images/[^'\"]+" js/contents.js | sort -u | while read -r p; do [ -f "$p" ] || echo "MISSING: $p"; done
```

Windows の Git Bash でも動く。壊れた参照があれば報告する。

## 5. 報告

以下の形式で、日本語で簡潔にまとめる：

- **現在の状態** — 最新コミット、未コミット変更の有無、リモートとの差分
- **前回の作業** — WORKLOG.md の最新エントリ
- **次にやること** — WORKLOG.md の TODO
- **問題** — 画像の欠損など、見つかった場合のみ

そのうえで「どれから進めますか？」と聞く。**勝手に作業を始めない。**

---

## セッション終了時（重要）

作業を終えるとき、または区切りがついたときは `WORKLOG.md` の先頭に
新しいエントリを追記して、コミットすること。これをやらないと次のマシンで文脈が切れる。

```markdown
## YYYY-MM-DD（作業したOS）

### やったこと
- （変更内容と、なぜそうしたか）

### 次にやること
- [ ] （残タスク）

### 判断メモ
- （後から「なぜこうなってる？」となりそうな決定があれば）
```

日付は推測せず、`date +%Y-%m-%d` で取得する。
